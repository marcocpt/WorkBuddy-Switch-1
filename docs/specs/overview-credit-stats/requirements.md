# 需求规格：概览页积分统计卡片

- 版本：v2（v1 草图于 2026-09-15 增量修订，见 §12）
- 项目：WorkBuddy Switch（OpenUsage）
- 来源：用户需求 + feature-development-workflow Intake 决策（覆盖范围=全部已保存账号，AskUserQuestion 2026-09-14 确认）

---

## 1. 目标

在「概览」页最顶部新增「积分统计」区域：为每一个已保存的账号（WorkBuddy、Trae CN、TRAE Work 三端合计）展示一张卡片，卡片包含「总积分（剩余）」与「近期到期积分及日期」两项核心信息，使用户无需逐端切换即可一眼看到各账号的积分余量与临近到期风险。数据获取方式以已有的两个参考实现为依据：changexbc/workbuddy-switch 的 CreditExpiry/CreditResource 模型（WorkBuddy billing 资源接口）与 TraeWorkAssistant 的积分看板思路（Trae 额度接口 + 到期/结算日期）。

## 2. 背景与现状

- 应用在钥匙串中保存三端账号快照：WorkBuddy 一套（`AccountStore`，每账号一份 AuthDocument 凭据）、Trae CN 与 TRAE Work 各一套（`TraeAccountStore`，每账号一份凭据快照）。
- 当前概览页只展示**当前选中 provider 的激活账号**的用量/额度（`quota`、`traeQuota`），其余已保存账号没有任何积分或到期信息可见。
- WorkBuddy 官方 billing 接口（`/v2/billing/meter/get-user-resource`）可按账号返回资源包列表（总量/剩余/到期时间）；Trae 额度接口（`ide_user_ent_usage`）返回套餐额度与下次结算/到期时间。
- 既有安全基线：凭据只在钥匙串；token 不落盘明文、不进日志、不进常规设置项；认证过期用内联提示替代模态弹窗。

## 3. 术语

| 术语 | 含义 |
|---|---|
| 积分（Credits） | 各端套餐/赠送包的剩余计费额度。WorkBuddy 为资源包剩余 Credits；Trae 按套餐单位（Credits 或 请求数）计 |
| 账号卡片 | 概览页积分统计区中，代表单个已保存账号的展示单元 |
| 近期到期 | WorkBuddy：剩余>0 且到期时间距现在 ≤ 7 天的资源包；Trae：下次结算/到期时间距现在 ≤ 7 天 |
| 总积分 | 账号在积分统计区显示的主数值：WorkBuddy 为全部资源包剩余之和；Trae 为额度剩余（Credits 单位）或请求剩余（请求单位）；不限量时显示「不限量」 |
| 三端 | WorkBuddy、Trae CN、TRAE Work 三个客户端 |

## 4. 范围（In Scope）

- 概览页最顶部新增积分统计区（位于现有 hero/欢迎横幅之上）。
- 每个已保存账号一张卡片：账号名（含当前激活标记）、总积分（剩余）、近期到期积分及日期。
- 覆盖全部已保存账号：WorkBuddy 走 billing 资源接口按账号拉取；Trae CN / TRAE Work 走额度接口按账号快照拉取。
- 积分数据随概览刷新（手动刷新、切换 provider/账号、自动周期刷新）一起刷新；刷新中显示进行中状态。
- 单个账号拉取失败（含登录过期）只在自身卡片上内联提示，不阻塞其余账号与其余概览内容。
- 认证过期沿用内联提示（不弹模态）。

## 5. Out of Scope

- 积分历史采集/持久化、趋势图、排行、签到（check-in）统计。
- 基于积分的自动切换或自动提醒。
- WorkBuddy OAuth token 刷新链路（现有应用不做 WorkBuddy token 刷新；过期账号卡片显示"登录已过期"内联提示）。
- 修改 WorkBuddy / Trae 客户端本体数据。
- 在积分区编辑、删除、切换账号。
- 积分到期日历视图。
- 缓存/离线数据：积分统计只反映最近一次成功刷新。

## 6. 功能需求（FR）

- FR-1 概览顶部积分统计区：概览页最上方（欢迎横幅上方）展示「积分统计」区域。
- FR-2 每账号一卡片：三端全部已保存账号各渲染一张卡片；无已保存账号时不渲染该区域（连空态也不占位）。
- FR-3 总积分展示：卡片主数值 = 账号剩余总额（见术语定义）；不明确/无数据时用「—」占位。
- FR-4 近期到期展示：卡片展示「近期到期积分 + 到期日期」；无近期到期时展示最近到期资源/结算日期或不展示（当不可知时为「—」）。
- FR-5 三端覆盖：WorkBuddy 账号取 billing 资源接口逐账号查询；Trae CN / TRAE Work 账号取额度接口逐账号快照查询。
- FR-6 账号身份与命名：卡片使用账号索引中的昵称，昵称缺失时用账号 ID 缩写；当前激活账号加「当前」标记。
- FR-7 随刷新更新：积分统计与概览刷新同一入口联动（概览刷新按钮、切换账号/provider、自动周期刷新）；刷新进行中显示加载状态。
- FR-8 故障隔离：任一账号查询失败（网络、格式、登录过期）只影响该卡片——该卡片显示原因内联，其余卡片正常。
- FR-9 认证过期内联：WorkBuddy/Trae 登录过期不弹模态，卡片内提示（如"登录已过期，请刷新登录后重试"）。
- FR-10 刷新竞态：刷新请求按代际（generation）判定，过期响应不覆盖较新的状态。
- FR-11 安全边界：卡片不展示任何 token；日志/索引/设置不出现凭据；HTTP 仅发往受信任官方主机。
- FR-12 始终展示近期到期：每个账号卡片都展示「近期到期」行（取该账号仍有剩余且带到期时间、到期最近的一个积分包的剩余额与日期；无此类包时展示最近到期/下次结算或「暂无可展示的到期」）。
- FR-13 查看全部积分包：卡片可展开查看该账号全部积分包明细（名称、剩余/总量、已用、到期时间、是否 7 天内到期/已到期）。WorkBuddy 取 billing 资源包；Trae 取额度响应中的权益包（credits 口径）。
- FR-14 按客户端分列：积分统计区按客户端（WorkBuddy / Trae CN / TRAE Work）分为三列，每列列头显示该 app 名称与卡片数；某客户端没有已保存账号时不渲染该列（也不留空列）。
- FR-15 到期排序（两层）：① 列内卡片按「最近到期」升序——「最近到期」取该卡片中仍有剩余且未到期的积分包里最早的到期日，无此类带日期的包时回落到卡片自身的最近到期/下次结算日；无任何到期信息的卡片排在列尾，拉取失败的卡片排在最后。② 卡片内「即将到期」预览与「查看全部积分包」明细共用同一顺序：仍有剩余且未到期的包按到期日升序在前，已到期/已用尽的包其次，无到期日的包最后。

## 7. 非功能需求（NFR）

- NFR-1 并发上限：三端账号并行拉取有上限（建议 ≤ 4 并发，避免瞬间大量请求）。
- NFR-2 超时：WorkBuddy 单账号请求超时 ≤ 12 秒，超时按失败处理；Trae 复用应用既有额度服务语义（单请求 20 秒 + 认证重试预算），不额外收紧，避免与用量读取行为不一致。
- NFR-3 兼容性：macOS 13+；Swift 5.7 构建；不引入新依赖。
- NFR-4 可达性：卡片与文本用中文；命中目标不小于 15px；加载/错误状态有可见反馈。
- NFR-5 规模：数十个账号量级下刷新无明显卡顿；额度刷新并行完成，整体等待受单账号超时约束。
- NFR-6 无副作用：积分统计只读网络接口与本机存储，不改写钥匙串、账号文件或 Trae 登录数据。

## 8. 验收标准（AC，映射 FR）

- AC-1（FR-1/FR-2）：概览页最顶部分别存在「积分统计」区域；仅当存在至少一个已保存账号时该区域可见。
- AC-2（FR-2/FR-3/FR-5）：分别保存 WorkBuddy、Trae CN、TRAE Work 各 ≥1 个账号后，概览积分区出现对应卡片，卡片数量 = 保存账号总数；每张卡片的「总积分」与对应账号官方接口返回的剩余一致（误差在接口精度内）。
- AC-3（FR-4）：构造一个含"7 天内到期资源"的 WorkBuddy 账号应答，卡片显示该批资源的剩余之和与最近到期日期；构造无近期到期的应答，卡片不显示错误并给出可读的最近到期信息（或无）。
- AC-4（FR-6）：激活账号的卡片带「当前」标记；昵称缺失时显示账号 ID 缩写。
- AC-5（FR-7）：点击概览刷新按钮后积分区进入加载态并更新为新数据；切换账号/provider 后积分区随之刷新。
- AC-6（FR-8/FR-9）：使其中某个已保存账号的查询返回 401/网络失败，该账号卡片显示对应内联原因（如"登录已过期"），其余账号卡片正常显示。
- AC-7（FR-10）：快速连续触发两次刷新，最终展示的积分数据来自第二次刷新（无旧数据回跳）。
- AC-8（FR-11）：刷新全程后，日志、账号索引、常规设置中不出现任何 token 或凭据；请求未发送到非官方主机。
- AC-9（FR-12）：任意账号都展示可见的「近期到期」行，含数值与日期，与最近到期包的剩余/到期一致。
- AC-10（FR-13）：展开卡片可查看该账号全部积分包（数量=接口返回的包数；WorkBuddy 资源包 / Trae 权益包），每包含名称、剩余/总量、已用与到期状态。
- AC-11（FR-14）：概览积分区按客户端分成三列，列头显示客户端名与该列卡片数；某客户端无已保存账号时该列不出现。
- AC-12（FR-15）：三列各自按「最近到期」升序排列，列内第一张卡片的到期日不晚于同列其余卡片；Trae 卡片以积分包到期日（而非下次结算日）参与排序，卡片内明细列表与「即将到期」预览顺序一致。

## 9. 失败路径与边界

| 场景 | 行为 |
|---|---|
| 某 WorkBuddy 账号 billing 401/403 | 该卡片内联提示登录过期；其余正常 |
| 某 Trae 账号额度 401/403 | 该卡片内联提示登录过期；不得改写 storage.json 或切换凭据 |
| billing/额度接口超时或网络失败 | 该卡片显示失败原因；其余正常 |
| 响应格式无法识别 | 该卡片显示"积分查询失败"，不展示伪造数字 |
| 无任何已保存账号 | 积分统计区不渲染 |
| 账号在刷新中途被删除/移除 | 结果集合按刷新开始时的快帐号集合渲染；下轮刷新自然消失 |
| Trae 账号为请求计费（unit=requests） | 卡片主数值显示请求剩余，到期显示下次结算日期 |
| Trae 不限量（total=nil） | 卡片主数值显示「不限量」，到期显示下次结算日期 |

## 10. 兼容性

- 与既有 OverviewView 布局共存：积分统计区插入 hero 之前，其余区块（hero、metrics、trend、quota、最近对话）不变。
- 三端数据源与现有 UsageService/TraeUsageService 的官方接口一致，不更换协议。
- 索引/钥匙串结构不变；不引入持久化文件。

- ~~卡片排序规则（本规格默认：WorkBuddy 按最近使用倒序 → Trae CN → TRAE Work；后续可改）。~~ v2 已定：改为按客户端分列（FR-14）+ 列内按最近到期升序（FR-15），不再使用「最近使用倒序」。

- 刷新频率沿用现有自动刷新周期（默认 10 分钟），不做独立节流。
