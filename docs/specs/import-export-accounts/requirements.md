# 需求规格：导入 / 导出所有已保存账号

- 版本：v1（未批准草图，等待自检后定版）
- 项目：WorkBuddy Switch（OpenUsage）
- 来源：用户需求 + feature-development-workflow Intake 决策

---

## 1. 目标

为 WorkBuddy Switch 提供「导出全部账号」与「导入账号」两类按钮能力：用户可将三端（WorkBuddy、Trae CN、TRAE Work）在 macOS 钥匙串中保存的全部账号快照，以单个加密文件的形式导出到任意位置；并可在本机从该文件恢复账号快照。核心诉求是账号数据可在本机之间迁移、备份与恢复，同时保持项目既有的安全基线（凭据仅存钥匙串、索引不含 token）。

## 2. 背景与现状

- 应用以钥匙串保存各端账号快照：WorkBuddy 一套、Trae CN 与 TRAE Work 各一套，分别有各自的账号索引与凭据存储。
- 目前没有任何批量导出 / 导入能力；换机或重装后需要重新登录并逐个保存账号。
- 既有安全基线：凭据只在钥匙串；索引（账号列表元数据）不含任何 access/refresh token；Token 不落盘明文、不进日志、不进常规设置项。

## 3. 术语

| 术语 | 含义 |
|---|---|
| 账号快照 | 某客户端（WorkBuddy / Trae CN / TRAE Work）单个已保存账号的完整数据：账号元数据 + 对应凭据数据 |
| 账号标识 | 用于判定"同一账号"的键：客户端 + 账号 userID（Trae 为 变体+userID；WorkBuddy 为 userID） |
| 备份文件 | 导出生成的单个文件，内含全部账号快照，使用用户密码加密 |
| 导入 | 从备份文件把账号快照恢复到本机钥匙串与账号列表 |
| 三端 | WorkBuddy、Trae CN、TRAE Work 三个客户端 |

## 4. 范围（In Scope）

- 导出：枚举三端全部已保存账号快照 → 组装记录 → 加密 → 写入用户选择的文件。
- 导入：读取用户选择的备份文件 → 解密并校验 → 写入钥匙串与账号列表 → 汇总报告。
- 密码交互：导出时输入两次（确认一致），导入时输入一次。
- 冲突策略：目标钥匙串已存在同一账号快照时跳过，不覆盖；其余正常导入。
- 结果反馈：导出 / 导入完成后展示数量汇总与失败详情。

## 5. Out of Scope

- 自动定时备份、云同步、自动上传。
- 选择性导出 / 导入（按客户端、按账号、按时间）。
- 覆盖式导入（替换既有账号快照）。
- 备份 WorkBuddy 会话、用量、额度、设置等非账号数据。
- 跨版本迁移：仅支持本项目产生的备份文件格式 v1。
- 在应用内预览备份文件内容。
- 修改 WorkBuddy / Trae 客户端本体数据。

## 6. 功能需求（FR）

- FR-1 导出全部账号：用户可触发导出，将三端全部已保存账号快照导出为单个文件。
- FR-2 导出文件加密：导出文件必须以用户密码派生密钥加密；无有效密码无法读取内容。
- FR-3 密码确认：导出时用户须输入密码两次且一致才可继续；密码为空或过短时必须阻止并提示。
- FR-4 导出内容完整性：每个账号记录须包含「所属客户端标识、账号元数据、镜像自钥匙串的凭据数据」；导出不做任何凭据改写或再加工。
- FR-5 导出无副作用：导出完成后本机钥匙串与账号列表保持不变；不删除、不新增、不修改任何账号数据。
- FR-6 空导出处理：当前没有任何已保存账号时，导出入口给出明确提示且不生成文件。
- FR-7 文件自描述：备份文件须自带格式标识与版本号，便于导入侧识别与拒绝不支持的版本。
- FR-8 导入账号：用户选择备份文件并输入密码后，恢复其中账号快照到本机钥匙串与账号列表。
- FR-9 导入冲突跳过：导入时若目标侧已存在同一账号标识的快照，则跳过该记录且不覆盖任何现有数据。
- FR-10 导入索引合并：对成功写入钥匙串的账号，在账号列表中不存在时追加；已存在时保留本机既有元数据（如自定义昵称），不做覆盖。
- FR-11 导入记录级校验：每个记录在写入前必须校验「凭据身份与元数据身份一致」；不一致的记录不得写入并计入失败报告。
- FR-12 导入整体校验：文件整体解析失败（格式损坏、版本不支持、密文认证失败、密码错误）时，本次导入整体中止，不写入任何账号。
- FR-13 导入部分失败：钥匙串写入失败的个别账号计入失败报告，不阻塞其余有效账号导入。
- FR-14 结果汇总：导出成功提示导出账号数与文件位置；导入完成提示 导入数 / 跳过数 / 失败数（失败附原因）。
- FR-15 操作互斥：导入 / 导出进行中，相关入口禁用并显示进行中状态；与正在进行的账号切换互斥（切换中不发起，备份中不切换）。
- FR-16 安全边界：密码、凭据、token 不得写入日志、账号索引、常规设置、聊天记录或任何非用户指定路径；导出文件仅存在于用户选择的路径。
- FR-17 入口形态：设置页提供「导出全部账号」与「导入账号」两个按钮，视觉与既有设置项一致。

## 7. 非功能需求（NFR）

- NFR-1 加密强度：文件加密不低于 AES-256；密钥派生使用带盐的密码派生函数，并在文件中携带随机盐与派生参数。
- NFR-2 兼容性：运行于 macOS 13+；与项目既有 Swift 5.7 构建兼容。
- NFR-3 规模：支持数百个账号记录的文件加解密与导入导出，无明显卡顿（本机 CPU 同机加解密）。
- NFR-4 可达性：按钮与提示文本使用中文；控件命中目标不小于 15px；进行中状态有可见反馈。
- NFR-5 错误可诊断：密码错误、文件损坏、版本不支持、账号校验失败等均给出可理解的错误提示。
- NFR-6 原子感知：导出写入采用临时同目录文件 + 替换，避免留下半成品；文件权限收敛（用户读写）。

## 8. 验收标准（AC，映射 FR）

- AC-1（FR-1/FR-5/FR-14）：导出一个含三端账号的环境后，生成的备份文件可打开，其中记录的账号数 = 当前三端已保存总数；导出前后钥匙串与账号列表无任何变化。
- AC-2（FR-2/FR-3）：导出必须输入两次一致的密码（≥ 8 位）才生成文件；用错误密码无法打开该文件。
- AC-3（FR-6）：无已保存账号时点击导出，提示"没有可导出的账号"，不生成文件。
- AC-4（FR-8/FR-11/FR-12）：用正确密码导入 AC-1 的备份文件，账号列表恢复记录中的全部账号；篡改文件任一字节或换成错误密码时，整体中止且不写入任何账号。
- AC-5（FR-9/FR-10）：再次导入同一文件时，全部记录因已存在（N/M/K 中 M = 全量）被跳过，本机既有数据（含自定义昵称）不变；导入前删除某一账号钥匙串后导入，该账号恢复且保留既有无冲突索引元数据。
- AC-6（FR-13/FR-14）：构造含个别非法记录的文件导入：非法记录计入失败 K，其余有效记录正常导入；汇总数字与实际情况一致。
- AC-7（FR-15）：切换进行中时导入 / 导出入口不可用；导入 / 导出进行中入口呈进行中状态。
- AC-8（FR-16）：导入 / 导出全程后日志、账号索引、常规设置中不出现 token 或密码明文。
- AC-9（FR-17）：设置页出现两个按钮，间距与样式与其他设置项一致，点击后有明确反馈。

## 9. 失败路径与边界

| 场景 | 行为 |
|---|---|
| 密码过短 / 两次不一致 / 为空 | 阻止继续，提示具体原因，不执行任何磁盘写入 |
| 密码错误 / 密文认证失败 | 导入整体中止，提示"密码错误或文件已损坏" |
| 文件非备份文件 / 版本不支持 | 导入整体中止，提示格式或版本问题 |
| 单个记录身份不一致（WorkBuddy 凭据 userID ≠ 元数据 userID；Trae 变体或其 userID 不一致） | 该记录计入失败，不写入，不影响其他记录 |
| 钥匙串写入失败（个别） | 该记录计入失败并给出原因，其余继续 |
| 无已保存账号时导出 | 提示无内容，不生成文件 |
| 切换进行中触发备份/导入 | 入口被禁用，无法触发 |
| 导出目标路径不可写 | 保留临时文件清理，报错并提示选择其他位置 |
| 导入进行中被再次触发 | 入口禁用/幂等，不重复执行 |

## 10. 兼容性

- 备份文件格式 v1 为本项目规范；导入侧仅接受 v1，遇到更高版本明确拒绝并提示升级应用。
- 同一备份文件可在安装了本项目、相同 provider id 命名规则的机器上导入（本机间迁移场景）。
- 不保证与其他应用格式互操作。

## 11. 决策自由度（实现方可自由决策）

- 加密算法族内的具体实现选择（认证加密方案、密钥派生参数、文件头布局），但必须满足 NFR-1 和 AC-2。
- 密码交互的具体 UI 组件与文件选择面板的呈现顺序。
- 代码组织、模块命名、函数划分（须满足可单测性要求与项目代码风格）。
- 数量汇总提示的具体文案。
