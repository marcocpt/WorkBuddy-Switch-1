## 1. 分工（WHO）

### 1.1 备份载荷层（纯数据，无 IO、无 UI）

- 职责：定义「账号记录」多态表示与「备份包」容器；备份包 ↔ JSON 的双向编解码；记录级校验规则；冲突决策规则。
- 不负责：密码学、文件读写、钥匙串、UI、Store 状态变更。
- 账号记录多态：两类变体——① WorkBuddy：账号元数据 + 凭据原始字节（不透明镜像）；② Trae：账号元数据 + Trae 凭据快照对象（其已具备编码能力）。记录携带所属客户端标识与账号标识。
- 备份包容器：格式标识、格式版本（当前 1）、导出时间、账号记录数组，并预留扩展空间（版本号向上兼容拒绝策略见 §5）。
- 冲突决策为纯函数：输入「目标侧钥匙串是否已存在该账号 + 索引中是否存在该账号」，输出 「跳过 / 写入钥匙串+合并索引」。规则见 §4。
- 记录校验为纯函数：对每个记录核验「凭据身份 ↔ 元数据身份」一致性（WorkBuddy 凭据解出的账号 ID 与元数据账号 ID 一致；Trae 凭据的客户端与账号 ID 与元数据一致）。

### 1.2 加密编码层（纯 CPU，只读写内存 Data）

- 职责：密码密钥派生、认证加密、备份文件字节布局（头部 + 密文）、字节 ↔ 备份包解译；以「用户指定密码 + 备份文件字节」为边界，无状态。
- 不负责：密码 UI、文件面板、落盘位置选择。
- 文件布局 v1（跨端稳定规格）：
  1. 魔数 8 字节（固定字节序列，用于快速识别是否为本项目备份文件）；
  2. 格式版本 1 字节（=1）；
  3. 密钥派生算法标识 1 字节（=1：PBKDF2-HMAC-SHA256）；
  4. 派生迭代次数 4 字节（大端）；
  5. 随机盐 16 字节（每次导出全新生成）；
  6. 随机初始化向量 12 字节（每次导出全新生成，认证加密用）；
  7. 密文 + 认证标签（长度随载荷而定）；
  8. 认证加密的附加明文数据 = 前 1~6 段的全部字节，使头部任何字节不可被静默篡改。
- 密钥派生：以密码 + 随机盐，采用 PBKDF2-HMAC-SHA256 至少 21 万次迭代派生 32 字节密钥。
- 认证加密：AES-256-GCM（随机 IV，见上），密文载荷 = 备份包 JSON 的 UTF-8 字节。
- 错误语义：魔数不符 / 版本不支持 / 参数非法 / 认证失败，均向上抛出可区分的原因（供 UI 直接呈现）。

### 1.3 编排层（MainActor，状态编排）

- 职责：导出 / 导入两个流程的编排；与两个账号仓库（WorkBuddy 仓库、Trae 仓库）交互读凭据与索引、写钥匙串与索引；聚合结果（导入数 / 跳过数 / 失败数及原因）；暴露进行中状态。
- 不负责：文件面板、密码 sheet 的具体 UI（由界面层负责），但负责流程顺序与互斥。
- 导出流程：登录账号 → 枚举三端账号 → 对每个账号取索引元数据 + 钥匙串凭据（取不到凭据的账号计入「无快照跳过」并汇总提示，不中断）→ 组包 → 加密 → 交给界面层写出文件 → 结果汇总。
- 导入流程：界面层取回「文件字节 + 密码」→ 解密出备份包 → 全量预校验（每个记录判定 通过 / 跳过 / 失败，失败原因分类：身份不一致 / 已存在 / 内容非法）→ 预校验完成后逐记录应用：通过且不冲突的写钥匙串（写入失败计入失败）→ 合并索引 → 结果汇总（导入 N / 跳过 M / 失败 K + 原因）。
- 互斥：与「正在进行的账号切换」互斥；进行中标记驱动入口禁用（见 §6）。
- 既有仓库需要增加两族方法（最小侵入）：① 枚举账号并取全部凭据镜像；② 写入单个凭据 + 合并索引条目。WorkBuddy 仓库的钥匙串组件当前为具体实现、不可注入——为满足单测，备份核心不直接触碰该组件，仓库这一层仅做薄封装；Trae 仓库已有注入能力，端到端路径可直接单测。

### 1.4 界面层（SwiftUI）

- 职责：设置页新增「账号数据」区；两个按钮；密码输入 sheet（导出二次输入确认、导入一次）；文档面板（保存 / 打开）；进行中状态渲染；结果与错误提示。
- 不负责：任何业务计算。

## 2. 数据流

### 2.1 导出

```text
用户点击「导出全部账号」
  → 校验：当前无任何账号？是 → 提示「没有可导出的账号」，退出
  → 弹出密码 sheet（两次输入一致校验，不满足则阻止）
  → 弹出保存面板（默认文件名含日期，扩展名固定）
  → 编排层：枚举三端 → 组包 → 加密（后台执行，入口禁用）
  → 临时文件写入 → 原子替换为目标路径（权限收敛）
  → 结果提示：导出 N 个账号（无快照跳过 S 个），文件位置
  → 本机数据无任何改动
```

### 2.2 导入

```text
用户点击「导入账号」
  → 弹出打开面板，用户选择备份文件（读取为字节）
  → 弹出密码 sheet（一次输入）
  → 编排层：解密 + 反序列化 + 全量预校验（后台执行，入口禁用）
       ├─ 整体失败（格式 / 版本 / 密码 / 认证）→ 整体中止，提示原因，退出
       └─ 通过 → 逐记录应用：判定 跳过(已存在) / 写入钥匙串（失败计入失败）→ 合并索引
  → 结果提示：导入 N 个 / 跳过 M 个 / 失败 K 个（附原因）
```

## 3. 状态

- 新增一个「备份进行中」布尔状态（应用级，MainActor 持有）：置真时两个按钮禁用并显示进行中指示；置假恢复。与切换互斥：导出 / 导入入口显式检查切换状态。
- 每组 sheet（密码输入、文件面板）为临时界面状态，不进业务状态。

## 4. 冲突与合并决策（纯函数，供单测）

按「账号标识」（客户端 + 账号 ID）判定：

| 钥匙串已有 | 索引已有 | 决策 |
|---|---|---|
| 是 | − | 跳过（不覆盖任何数据），计入跳过 M |
| 否 | 是 | 写钥匙串；索引保留本机既有元数据（如自定义昵称，不覆盖），仅确保条目存在 |
| 否 | 否 | 写钥匙串；索引追加导入的元数据 |

即：跳过判定只看钥匙串是否已有该凭据快照；索引合并只做「存在则保留、缺失则追加」，永不删除或改写既有元数据。损坏状态（索引有 / 钥匙串无）经导入自然修复而不覆盖元数据。

## 5. 兼容性与版本策略

- 备份文件格式 v1；导入侧遇到高于 1 的版本明确拒绝，提示「备份文件版本过高，请升级应用」。
- 魔数与版本均在头部，解密前即可判定；认证绑定头部防降级与篡改。
- 记录内 Trae 凭据直接复用其既有编码，避免自行重定义造成可读性/互操作回归。

## 7. NFR 落实

- NFR-1：PBKDF2 21 万次 + AES-256-GCM，随机盐 + 随机 IV，见 §1.2。
- NFR-2 / NFR-3：随项目 Swift 5.7 / macOS 13 构建；加解密为纯 CPU 后台执行，数百记录规模轻松满足。
- NFR-4 / NFR-5：中文提示、大按钮、进行中反馈；错误原因分类映射为用户可读文案。
- NFR-6：临时同目录文件 + 原子替换 + 0600 权限（沿用项目既有原子写模式）。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 用户遗忘导出密码 → 备份永久不可读 | 导出时明文提示「密码无法找回，请妥善保管」；备份文件头不含可降级旁路 |
| 备份文件被篡改 / 弱密码被爆破 | GCM 认证 + 头绑定；PBKDF2 高成本迭代；密码最短 8 位 |
| 导入环境差异（生产 token 校验失败，如过期） | 导入仅恢复钥匙串数据，不触发切换；切换时的既有校验在用户主动切换时才执行 |
| WorkBuddy 索引有 / 钥匙串无的损坏态 | 导出跳过提示；导入按 §4 自然修复 |
| 部分钥匙串写入失败（系统级） | 逐记录捕获，计入失败并见结果汇总 |
| 新文件加入导致自测脚本漏编 | 登记测试脚本源文件清单（test.sh），作为实现包的一部分 |
